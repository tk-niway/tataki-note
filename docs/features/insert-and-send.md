# 書いた文章を挿入する・送信する

パネルで書いた文章は、確定キーを押すと、パネルを開いたときに使っていたアプリの入力欄に入ります(挿入)。
「確定+送信」のキーを割り当てると、挿入したあと、そのアプリで Enter を押したのと同じように送信まで行えます。

挿入と送信には、アクセシビリティの許可が要ります([アクセシビリティの許可](accessibility.md))。

## 挿入する

1. 文章を入れたいアプリ(テキストエディタやブラウザ、チャットアプリなど)を前面にして、入力欄にカーソルを置きます。
2. ホットキー `⌥⇧Space`(Option + Shift + Space。既定値。変え方は [ホットキーを変える](settings.md#ホットキーを変える))か、メニューバーの TatakiNote のアイコン →「パネルを開く」で、パネルを開きます。
3. 文章を書きます。`↩`(Return)は改行です。
4. 確定キー(初期設定は `⇧⌘↩`(Shift + Command + Return))を押します。パネルが閉じ、手順 1 のアプリに文章が入ります。挿入だけで、送信はしません。挿入して送信までしたいときは、確定+送信キー(初期設定は `⌘↩`(Command + Return))を使います([挿入して送信する](#挿入して送信する))。キーは設定で変えられます([「一般」の項目](settings.md#一般の項目))。

確定キーは挿入だけを行います。内容を確かめてから、挿入先で自分で Enter を押して送信します。

## 確定のキー

パネルには、キーを割り当てられる操作が2つあります。設定の記録ボックスで、修飾キー(⌘・⌥・⌃・⇧のいずれか)を含む好きなキーの組み合わせを登録します([確定キーと確定送信キーを登録する](settings.md#確定キーと確定送信キーを登録する))。

| 操作 | 何をするか | 既定値 |
|---|---|---|
| 確定 | 文章を挿入します | `⇧⌘↩`(Shift + Command + Return) |
| 確定+送信 | 文章を挿入したあと、挿入先で Enter を送ります([挿入して送信する](#挿入して送信する)) | `⌘↩`(Command + Return) |

- Return キーとテンキーの Enter キーは同じキーとして扱います。Caps Lock や fn キーの状態は関係ありません。`⌘K` のような、Return 以外のキーも登録できます。
- 同じキーは両方に登録できません。もう一方で使っているキーを登録しようとすると受け付けられず、理由が表示されます([確定キーと確定送信キーを登録する](settings.md#確定キーと確定送信キーを登録する))。
- キーの登録・変更は [「一般」の項目](settings.md#一般の項目) を見てください。変えると、パネルが開いていても次のキー入力から効きます。

### 設定ごとのキーの動き

初期設定(確定は `⇧⌘↩`、確定+送信は `⌘↩`)のときの動きです。

| 押したキー | 動き |
|---|---|
| `⇧⌘↩`(Shift + Command + Return) | 確定(挿入だけ。Enter は送りません) |
| `⌘↩`(Command + Return) | 確定+送信(挿入して Enter を送信) |
| `⇧↩` / `↩`(Return) | 改行 |

- 確定キー・確定+送信キーのどちらにも登録していない Return 系のキー(`⇧↩`・`⌘↩`・`⇧⌘↩` など)は、修飾キーなしの `↩` と同じく改行になります。
- 日本語入力などで変換中(未確定の文字がある間)は、どのキーも入力メソッドの確定になり、パネルの確定にはなりません。
- 確定キーの登録を消すと、確定キーでは挿入できません。確定+送信キーも登録していなければ、パネルからは挿入も送信もできず、下書きを書くだけになります(`esc` で閉じれば下書きは残ります)。

## 挿入して送信する

確定+送信キーを割り当てると、そのキーで、文章を挿入したあと、挿入先に修飾キーなしの Enter を1回送ります。チャットアプリなどでは、そのまま送信されます。

1. 送信したい入力欄のあるアプリ(チャットアプリなど)を前面にして、入力欄にカーソルを置きます。
2. パネルを開いて、文章を書きます。
3. 確定+送信キーを押します。パネルが閉じ、手順 1 のアプリに文章が入り、続けて Enter が送られます。

確定キーに「⌘K」、確定+送信キーに「⇧⌘↩」を登録したときの例:

| 押したキー | 結果 |
|---|---|
| `⌘K` | 確定(挿入だけ。Enter は送りません) |
| `⇧⌘↩` | 確定+送信(挿入して Enter を送ります) |
| `⇧↩` / `↩` | 改行 |

確定キーを登録していないときは、確定+送信キーでだけ挿入できます。

- **送信は取り消せません。** 挿入先の入力欄に元からあった文章も、Enter でまとめて送られます(挿入先のアプリの動きです)。
- 書いている途中の誤送信を防ぐのが TatakiNote の目的なので、送信するのは、自分でキーを登録して、そのキーを押したときだけにしています。
- 送る Enter に、確定+送信キーで押した `⇧` や `⌘` が混ざらないよう、押している修飾キーが離れるのを待ってから送ります(約 0.5 秒待っても離れないときは、そのまま修飾キーなしで送ります)。
- 送る直前に、前面のアプリが挿入先でなくなっていたら、Enter を送りません。たとえば `⇧⌘↩` の `⌘` を押したまま、`⌘Tab` で別のアプリに切り替えたときです。文章は挿入先に入っていて、Enter を送らなかったことの通知は出ません。
- 変換中に確定+送信キーを押しても、入力メソッドの確定になるだけで、挿入も送信もされません。
- 文章が空のまま押すと、パネルが閉じるだけで、挿入も送信もされません。
- 挿入できなかったときは、Enter も送りません([確定したときの動き](#確定したときの動き))。

## 確定したときの動き

確定(または確定+送信)すると、まずパネルが閉じ、その後は次のどれかになります。

| 状況 | 動き | 書いた文章 |
|---|---|---|
| 文章が空 | パネルが閉じるだけです。案内も通知も出ません | 空のまま |
| アクセシビリティの許可が無い | 「アクセシビリティの許可」の案内が開きます([確定で案内が開いたとき](accessibility.md#確定で案内が開いたとき))。挿入はしません | 下書きに残ります |
| 挿入先のアプリが分からない | 通知で知らせます | 下書きに残ります |
| 挿入先のアプリを前面にできなかった(約1秒待っても前面にならなかった・アプリが終了していた) | 通知で知らせます。貼り付けはせず、クリップボードにも触れません | 下書きに戻ります |
| 挿入先で入力欄が選ばれていなかった(ボタン・一覧・Web ページの本文などが選ばれていた) | 通知で知らせます。貼り付けはせず、クリップボードにも触れません | 下書きに戻ります |
| 上の2つで、その間にパネルで新しい文章を書き始めていた | 通知で、確定した文章を下書きに戻せなかったことを知らせます | 新しい文章が残り、確定した文章は戻りません |
| 挿入できた | 挿入先に文章が入り、クリップボードは元の内容に戻ります | 下書きは空になります |

- 挿入できたときは、ドラッグで変えていたパネルの大きさも元に戻ります(次に開くときは既定の大きさ。初期値は 520 × 340 ポイント)。挿入できなかったときと、空のまま確定したときは、変えた大きさが保たれます([パネルの大きさ](panel.md#パネルの大きさ))。
- 入力欄かどうかは、アクセシビリティの仕組みで調べます。入力欄かどうか分からないアプリ(アクセシビリティに対応していないアプリなど)では、そのまま貼り付けます(確定+送信なら Enter も送ります)。ただし Finder(デスクトップを含む)では、入力欄かどうか分からないときも入力欄ではないとして扱い、貼り付けずに下書きに残します(名前の変更の欄など、入力欄には今までどおり入ります)。
- 確定+送信でも、分かれ方は同じです。挿入できなかったときは Enter を送りません。
- 下書きに残った・戻った文章は、パネルを開けばそのまま残っています。原因を直してから、もう一度確定してください。

## 挿入先の決まり方

- 挿入先は、パネルを**閉じた状態から開いた瞬間**に前面だったアプリです。自動表示で開いたときも同じです。
- そのとき TatakiNote 自身が前面だった(設定ウィンドウを開いていたときなど)ときは、最後に前面になった TatakiNote 以外のアプリになります。TatakiNote を起動したときから覚え始めます。
- どちらも無いときは「挿入先のアプリが分からない」になります。
- パネルを開いている間は、挿入先は変わりません。開いたままメニューの「パネルを開く」を選び直しても、最初に開いたときのアプリのままです。

## 通知とビープ音

挿入できなかったときは、通知(バナー)で知らせます。

- 通知のタイトルは「文章を挿入できませんでした」です。
- 本文は、理由の文と、書いた文章がどうなったかの文でできています。

| 理由 | 理由の文 |
|---|---|
| 挿入先のアプリが分からない | 「挿入先のアプリが分かりませんでした。」 |
| 挿入先のアプリを前面にできなかった | 「“アプリ名”に挿入できませんでした。」(アプリ名が分からないときは「挿入先のアプリに挿入できませんでした。」) |
| 挿入先で入力欄が選ばれていなかった | 「“アプリ名”で入力欄が選ばれていませんでした。」(アプリ名が分からないときは「挿入先のアプリで入力欄が選ばれていませんでした。」) |

| 書いた文章 | 続く文 |
|---|---|
| 下書きに残った・戻った | 「文章はパネルに下書きとして残っています。」 |
| パネルに新しい文章があったので戻せなかった | 「パネルに新しい文章があるため、この文章は下書きに戻せませんでした。」 |

通知が出せないときは、代わりにビープ音を鳴らします。

| 通知の状態 | 動き |
|---|---|
| 通知を出せる(TatakiNote の通知を許可していて、バナーが出る設定) | 通知を出します |
| まだ通知の許可を尋ねていない | 通知の許可を尋ねるダイアログが出ます。許可すれば通知、許可しなければビープ音です |
| 通知を出せない(許可していない・バナーが出ない設定・通知の表示がオフなど) | ビープ音を鳴らします |
| 通知を出すのに失敗した | ビープ音を鳴らします |

- 続けて失敗しても通知は積み重ならず、最新の1件に置き換わります。
- TatakiNote が前面のとき(設定ウィンドウを開いているときなど)も、バナーで出します。
- 通知に音は付けません。

## クリップボードの扱い

挿入は、クリップボードに文章を入れて `⌘V`(Command + V)を送る方法で行います。コピーしていた内容は、挿入の後に元に戻ります。

- 挿入している間、クリップボードには一時的に、挿入する文章だけが入ります。
- クリップボード履歴アプリには、一時的な内容だという印を付けて渡します。履歴に残さないかどうかは、履歴アプリ次第です。
- `⌘V` を送った約 0.5 秒後に、元のクリップボードを、すべての項目・すべてのデータの種類(画像・リッチテキストなどを含む)ごと元に戻します。確定+送信のときは、Enter を送った後に戻します。
- その間に自分や他のアプリが何かをコピーしていたら、その内容を上書きしません(元に戻しません)。
- 中身をその場で取り出せない種類のデータ(提供元のアプリが後から渡す約束だけをしているデータなど)は、元に戻らないことがあります。
- 続けて確定して挿入が重なったときは、前の挿入でクリップボードを元に戻し終えてから、次の挿入を始めます。
